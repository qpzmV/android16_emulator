`ProvisionActivity` 是 Android 原生系统（AOSP）中一个非常特殊且关键的组件。它是 AOSP 自带的默认“系统开机引导/设置向导”（Provision 应用） 的核心 Activity（源码通常位于 `packages/apps/Provision/src/com/android/provision/ProvisionActivity.java`）。

简单来说，它的唯一使命就是：**代表系统完成“第一次开机初始化”，然后“自杀”，让用户能够看到并进入桌面。**

为了让你在定制 Android 16 系统时心中有数，我们来看看它的核心工作原理和它的具体职责：

---

### 1. `ProvisionActivity` 核心做哪几件事？

当全新刷机的系统第一次开机时，系统发现还没有进行初始化，就会拉起 `ProvisionActivity`。由于 AOSP 是开源纯净版，它没有商用手机（如华为、小米或 Google Pixel）那种华丽的欢迎界面、联网激活、指纹设置等步骤，它的界面通常是一片空白或者极简的提示。

它在后台默默执行以下三步：

#### 第一步：向系统数据库写入“通关文牒”（最核心职责）

它会向系统的全局设置数据库（Settings Provider）中写入两个最重要的标志位，把它们的值从 `0` 改为 `1`：

* **`Settings.Global.DEVICE_PROVISIONED = 1`**（设备已准备就绪）
* **`Settings.Secure.USER_SETUP_COMPLETE = 1`**（用户设置已完成）

这两个标志位是给 `SystemServer`、`ActivityManagerService (AMS)` 和 `WindowManagerService (WMS)` 看的。系统服务一旦看到这两个值变成 `1`，就知道“开机向导已经走完了，可以安全地放行所有应用和手势了”。

#### 第二步：激活默认桌面（Launcher）

在第一次开机时，普通的第三方桌面或者系统自带桌面通常是被“压制”状态的。`ProvisionActivity` 会确保系统的默认桌面（Launcher）处于启用（Enabled）状态，准备接管屏幕。

#### 第三步：自残/自杀（永不再启）

这是它最酷的地方。为了确保用户**只有在第一次开机或恢复出厂设置时**才看到它，`ProvisionActivity` 在执行完上述两步后，会调用 Android 底层 API：

```java
PackageManager pm = getPackageManager();
ComponentName name = new ComponentName(this, ProvisionActivity.class);
pm.setComponentEnabledSetting(name, PackageManager.COMPONENT_ENABLED_STATE_DISABLED, 0);

```

这段代码的意思是：**在系统组件清单里，把自己永久禁用（Disabled）**。
执行完这行代码后，它会调用 `finish()` 结束自己。因为他把自己禁用了，以后无论是重启手机、扣电池还是正常开关机，系统都不会再理会它，而是直接跳过它去启动桌面。

---

### 2. 它和你上一问遇到的 `SdkSetup` 有什么关系？

它们是**同胞兄弟**，功能几乎一模一样，只是服务的对象不同：

* **`ProvisionActivity` (Provision.apk)**：是面向通用真实设备（如手机、平板）的 AOSP 标准开机向导。
* **`SdkSetup.apk`**：是面向模拟器（Emulator/Goldfish）环境的专用精简开机向导。

因为模拟器不需要用户去设置 Wi-Fi、录指纹，所以 Google 写了一个极为精简的 `SdkSetup` 来代替标准的 `Provision`，在模拟器开机时秒速静默写完标志位，直接进桌面。

---

### 3. 在裁剪/定制 AOSP 时，关于它有什么坑？

如果你在精简系统、做 ROM 定制，或者想自己写一个炫酷的“厂商开机向导”（比如叫 `MySetupWizard`），你必须高度注意 `Provision`：

1. **如果你想用自己的开机向导代替它**：
你需要在你的新应用的 `AndroidManifest.xml` 中配置特殊的 Intent-Filter（包含 `CATEGORY_HOME` 和高优先级的 `DEFAULT`），去拦截第一次开机事件。并且，**你的应用必须负责把 `DEVICE_PROVISIONED` 和 `USER_SETUP_COMPLETE` 写成 `1`，并禁用掉自己**。否则系统会卡死。
2. **如果你简单粗暴地在 `PRODUCT_PACKAGES` 里把 `Provision` 裁掉了，且没有替换者**：
系统开机后，由于没有任何应用去把那两个全局标志位改成 `1`，系统的窗口管理器（WMS）会认为“设备还没初始化完毕”。
**后果就是：系统会拒绝拉起桌面，手机会一直停留在黑屏状态，或者只显示顶部的状态栏，按 Home 键、返回键全都没反应。**

### 💡 绕过它的黑科技

如果你在编译系统时不想编译任何开机向导应用（把 `Provision` 和 `SdkSetup` 全裁了），为了防止开机黑屏，你可以在电脑上连接 adb，手动用命令行帮它们把活干了：

```bash

```

只要这两行命令敲下去，系统底层就会瞬间“大彻大悟”，立刻把桌面（Launcher）拉起来。

## 根因

`out/host/linux-x86/bin/process-compat-config` 是一个 stub 脚本，它把所有 compat config XML 都写成空的 `<compat-config></compat-config>`。这导致运行时只能加载 **6 个** ChangeId，而正常 AOSP 有几十上百个。

```java
@ChangeId
@EnabledSince(targetSdkVersion = Build.VERSION_CODES.VANILLA_ICE_CREAM)
private static final long ENFORCE_EDGE_TO_EDGE = 309578419;
```

缺失这个 ChangeId 导致 `isEdgeToEdgeEnforced()` 的判断链异常 — 虽然最终 edge-to-edge 仍然被强制执行了（通过 `com.android.window.flags.Flags.enforceEdgeToEdge()`），但缺少 per-app 的 compat change 注册会导致系统对 IME 的 `fitSides` 计算不包含 `BOTTOM`，键盘不知道要为导航栏留出间距：
